# ROXI — Сохранение мира и профиля игрока (Этап 4)

**Версия:** 0.2
**Статус:** ✅ утверждено разработчиком 2026-11-20: технические решения Х1–Х8; **П1 — как в Rust (спящие персонажи)**; П2–П6 — значения «По умолчанию».
**Основание:** `ROXI_GDD.md` §12, §13, открытые вопросы №16–17; `ROXI_Network_Architecture.md` Р4 (✅ всё хранится на сервере, как в Rust; профиль — локально на сервере, через отдельный интерфейс; вайпы отложены).

---

## 1. Проблема сейчас

После перезапуска сервера пропадает всё: постройки, спальники, контейнеры, предметы на земле, инвентари. Кроме того, **при выходе игрока из игры его персонаж удаляется вместе с инвентарём** — вещи теряются безвозвратно. Для survival это критично.

## 2. Что требует GDD / уже решено

| Требование | Источник |
|---|---|
| Состояние мира хранится на игровом сервере | Р4 ✅ |
| Постоянный профиль (уровень, достижения) хранится отдельно от мира и переживает вайп | GDD §12, §13; Р4 ✅ |
| Вайпы пока не реализуем, но разделение «мир / профиль» закладываем сразу | Решение 2026-11-20 ✅ |
| Система уровня и достижений **не определена** (GDD §13) | → храним поля, логику не придумываем |

## 3. Технические решения (рекомендации)

### Х1. Два независимых хранилища

| Хранилище | Что | Вайп (в будущем) |
|---|---|---|
| **Мир** (`World`) | Элементы построек, спальники/кровати (с перезарядкой), контейнеры с добычей, предметы на земле, состояние персонажей вышедших игроков | Удаляется |
| **Профили** (`Profiles`) | Постоянный ID игрока, уровень, достижения (поля из GDD §13) | Не трогается |

Доступ — через интерфейс `IRoxiWorldStore` / `IRoxiProfileStore`. Если позже понадобится общий профиль для нескольких серверов или база данных — меняется только реализация интерфейса.

### Х2. Формат хранения

| Вариант | Плюсы | Минусы |
|---|---|---|
| **А. Файл-снимок (`USaveGame`)** — как файл мира в Rust | Просто, без плагинов; один файл = один мир; вайп = удалить файл | Каждый раз пишется весь мир |
| Б. SQLite (`SQLiteCore` есть в движке) | Частичные обновления, устойчивость к сбоям | Больше кода, схема БД, миграции |

**Рекомендация: А.** Для мира 4×4 км со всеми постройками снимок займёт единицы–десятки МБ — это нормально для записи раз в несколько минут. Если замеры покажут проблему — переход на Б только внутри `IRoxiWorldStore`.

### Х3. Когда сохранять (как в Rust)
- **Периодически** — по умолчанию раз в 5 минут (настраивается, П3).
- **При штатной остановке сервера.**
- **Отладочной/админской командой** `roxi.Save`.

Сбор данных — на игровом потоке (быстро: только копирование структур), запись файла — **в фоновом потоке**, чтобы не было рывка. Запись атомарная: во временный файл, затем переименование — сбой во время записи не портит предыдущее сохранение.

### Х4. Загрузка
- При старте сервера, **до** подключения игроков.
- В файле — версия формата и имя карты. Несовпадение → мир не загружается, файл не перезаписывается, в лог — понятная ошибка.
- Повреждённый файл → загрузка из резервной копии.

### Х5. Резервные копии
Хранить **3 последних** сохранения (ротация). Место — `Saved/SaveGames/<ИмяМира>/`. Имя мира задаётся параметром запуска сервера (`-RoxiWorld=<имя>`, по умолчанию `default`) — на одной машине можно держать несколько миров/серверов.

### Х6. Что сохраняется у объектов

| Объект | Данные |
|---|---|
| Элемент постройки | Тип (ссылка на описание), положение, поворот, здоровье, владелец |
| Спальник / кровать | Класс, положение, здоровье, владелец, оставшаяся перезарядка |
| Контейнер с добычей | Положение, подпись, содержимое |
| Предмет на земле | Положение, стопка |
| Персонаж вышедшего игрока | Положение, поворот, здоровье, инвентарь, пояс (см. П1) |

Предметы хранятся по ID описания (`PrimaryAssetId`), а не по пути к файлу — переименование папок не ломает сохранения. Если описание предмета удалено из игры, предмет при загрузке пропускается с предупреждением в логе.

### Х7. Проверка и нагрузка
- Сценарий: построить, поставить спальник, выбросить предметы, умереть (контейнер), выйти и зайти игроком, перезапустить сервер → всё на месте.
- Замер: сохранение и загрузка 5 000 / 20 000 элементов — время сбора на игровом потоке, размер файла, время загрузки.
- Повреждённый файл и файл от другой карты — корректный отказ.

### Х8. Отладка
`roxi.Save` (сохранить сейчас), `roxi.Save.Info` (что и когда сохранено), лог с временем и размером каждого сохранения.

## 4. Вопросы к разработчику

| № | Вопрос | Как в Rust | По умолчанию |
|---|---|---|---|
| **П1** | **Что происходит с персонажем при выходе из игры** | Персонаж **остаётся в мире спящим**: его можно убить и обыскать | **Безопасный выход:** персонаж исчезает из мира, его состояние сохраняется и восстанавливается при входе на том же месте. ⚠ Позволяет «выйти из игры, чтобы спастись» в бою; вариант Rust от этого защищает, но это новая механика |
| П2 | Сохраняются ли предметы на земле при перезапуске | Да (и сами исчезают через несколько минут) | Да, без исчезновения (В9 не решён) |
| П3 | Интервал автосохранения | ~10 мин (настраивается) | 5 мин |
| П4 | Поля профиля | — | Только уровень и достижения из GDD; логики начисления нет (GDD §13 не определяет), уровень = 1, список достижений пуст |
| П5 | Очередь крафта при выходе | — | Отменяется с возвратом ресурсов в инвентарь (до сохранения) |
| П6 | Перезарядка спальников переживает перезапуск | Да | Да — сохраняется оставшееся время |

⚠ **П1 — главный вопрос этапа**: он определяет не только сохранение, но и игровой процесс (бегство из боя, рейды на «спящих»).
