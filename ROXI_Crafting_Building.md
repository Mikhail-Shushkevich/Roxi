## 1. Что требует GDD (и только это)

| Требование | GDD |
|---|---|
| Крафт — одна из основных механик | §6.2 |
| Игрок может скрафтить спальник и кровать | §6.2, §5.3 |
| Спальник/кровать размещаются в мире и служат точками возрождения | §5.3 |
| После смерти игрок выбирает доступную точку возрождения; если их нет — случайная точка | §5.3 |
| Строить можно почти в любой точке карты | §6.1 |
| Нельзя строить на воде, на территории POI и в защитных радиусах вокруг POI | §6.1 |

**Чего в GDD нет** (и что я по умолчанию НЕ делаю — см. §4): сбор ресурсов как система, верстаки и уровни крафта, набор элементов построек, уровни материалов и улучшения, устойчивость построек, права на строительство (аналог шкафа Rust), гниение построек, двери и замки. Всё это — механики, которые нельзя добавлять без вашего решения.

## 2. Технические решения (рекомендации)

### К1. Рецепты
`URoxiRecipeDefinition` (`UPrimaryDataAsset`, как предметы): входные предметы с количеством, результат с количеством, время крафта, поле «требуемая станция» (зарезервировано, пусто — В-С4).

### К2. Выполнение крафта
| Вариант | Суть |
|---|---|
| **А. Очередь с временем (как в Rust)** | Ресурсы списываются при постановке в очередь; предмет выдаётся по завершении; отмена возвращает ресурсы. Очередь — на сервере, клиенту реплицируется только владельцу |
| Б. Мгновенный крафт | Проще, но не как в Rust |

**Рекомендация: А.** Очередь живёт на персонаже: при смерти незавершённые позиции возвращают ресурсы в инвентарь до переноса в контейнер с добычей.

### К3. Размещаемые объекты (спальник, кровать, позже — ящики и т.п.)
- У определения предмета появляется поле «размещаемый класс». Использование такого предмета = попытка поставить объект.
- Клиент показывает «призрак» и шлёт серверу желаемую позицию; **сервер проверяет**: дистанция до игрока, опора под объектом, наклон, пересечения с другими объектами, запретные зоны (К6). Только после этого предмет списывается и объект появляется.
- Базовый класс `ARoxiDeployable`: здоровье, владелец, «спящий» по сети.
- Визуальный «призрак» — часть UI; до финального UI — размещение отладочной командой перед игроком.

### К4. Точки возрождения и выбор после смерти
- `ARoxiSleepingBag` (спальник и кровать — один класс с разными параметрами): владелец, перезарядка.
- Сервер отправляет игроку **только его** точки (как в Rust: чужие спальники не видны в списке). Клиент выбирает → `ServerRequestRespawn(Point)`; сервер проверяет владельца и перезарядку. Нет доступных точек → случайная (как сейчас).
- Владелец определяется по постоянному ID игрока (`UniqueNetId` онлайн-подсистемы), а не по контроллеру — чтобы точки сохранялись после переподключения.

### К5. Элементы построек
- Согласно Р3: **один актор на элемент**, у каждого своё здоровье; «спящие» по сети, обновления — только при изменении.
- **Привязка (snapping) по сетке:** фундамент ставится на землю; остальные элементы — только к гнёздам существующих элементов (стена на край фундамента, перекрытие на верх стен). Это нужно для любой системы строительства жанра и не является новой механикой.
- Набор элементов, материалы, улучшения, устойчивость — вопросы В-С7…В-С10.

### К6. Запретные зоны (§6.1)
- `ARoxiNoBuildZone` — объект, который дизайнер ставит на карту (сфера или прямоугольник) вокруг POI; радиус задаётся на каждом экземпляре (открытый вопрос №6). Проверяется при размещении любых построек и размещаемых объектов.
- **Вода:** система воды для карты ещё не выбрана (решение этапа «Мир»). Сейчас — проверка «точка в водном объёме» (`PhysicsVolume` с флагом воды) + запретные зоны вокруг водоёмов. Когда будет выбрана система воды, проверка расширяется без изменения остальной логики.

### К7. Сеть и нагрузка
На стенде — замер 5 000 элементов построек (спящих) и массовой постройки/разрушения. Если «актор на элемент» окажется слишком дорогим — переход к варианту Б из Р3 выносится на согласование (логика для игрока не меняется).

### К8. Отладка
Команды: `RoxiCraft <Recipe>`, `RoxiCraftCancel`, `RoxiPlace <inv|belt> <slot>` (поставить размещаемый предмет перед собой), `RoxiBuild <Piece>`, `RoxiRespawn [index]`. HUD: очередь крафта, список точек возрождения, причина отказа размещения.

### К9. Тестовые данные
Реальных ресурсов нет (открытый вопрос №8) → рецепты спальника, кровати и стоимость построек на тестовых предметах `DEV_TestItemA/B`. Заменяются, когда утвердите список ресурсов.

## 3. Предлагаемый план Этапа 3

1. Рецепты и очередь крафта (К1, К2).
2. Размещаемые объекты + проверки размещения + запретные зоны (К3, К6).
3. Спальник и кровать: крафт, размещение, выбор точки возрождения (К4).
4. Базовые элементы построек с привязкой и здоровьем (К5) — в объёме, который вы утвердите в В-С7…В-С12.
5. Проверка на 2 клиентах + нагрузочный замер (К7).

Каждый пункт — отдельный коммит.
